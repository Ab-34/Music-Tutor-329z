# Tutor Console GUI: Implementation Plan (2026-11-05)

Implements `docs/superpowers/specs/2026-11-05-gui-design.md`. The user approved building it directly after the spec,
with inline execution on branch `gui-console`.

## Prerequisite (already in the working tree)
Commit the OpenRouter wrapper, the budget ledger and the agent/B2 migration as their own commit first, because the GUI
depends on `tutor.llm.chat`, `read_ledger`, `total_spend` and `BudgetExceeded`.

## Steps
1. **Agent hook:** add `on_event` to `run_agent` (`llm` and `tool` events). Test it with a fake `llm.chat`.
2. **Dependencies:** add the `gui` extra (`streamlit`, `plotly`) to `pyproject.toml` and install it.
3. **`gui/sources.py`:** a `Source` dataclass, the bundled example with ground truth, eval cases from the manifest
   (paths resolved against the repo root) and `save_upload`. Unit-test case listing from a temporary manifest.
4. **`gui/components.py`:**
   - system lists (`HIDDEN_SYSTEMS = {"audio_llm"}`) and checks for the key and the audio extras
   - `score(gt, pred)` built on `grade_detection.match`, giving P/R/F1 and a status for each error
   - `piano_roll(...)` as a Plotly figure
   - `wav_bytes(notes)` through `synth` and the stdlib `wave`
   - `midi_bytes(notes)`
   - error-table rows

   Unit-test `score` and the piano-roll trace counts.
5. **`gui/jobs.py`:**
   - `launch` (one job at a time, `job.json`, log file), `status` (running/finished/stopped, progress, spend) and
     `stop`
   - `list_runs`, `load_run` (grading partial runs from the manifest) and `estimate_cost` (average cost per case
     over past runs of the same system)

   Unit-test `status` and partial grading on a fake run directory.
6. **`gui/common.py`:** page setup (path, chdir to the repo root, page config) and the sidebar (model, spend vs budget,
   key and audio status).
7. **Pages:** `app.py` (home: what each page does and a quick health check), `1_Assess.py` (live trace using
   `st.status`, results kept in `session_state`, opening a stored prediction from Eval), `2_Simplify.py`, `3_Memory.py`,
   `4_Eval.py` (launch form with estimate, live panel as an `st.fragment(run_every=3s)`, results, opening a case in
   Assess, comparing runs, building a small offline eval set when there's no manifest), `5_Spending.py`.
8. **AppTest smoke tests:** every page loads, and B0 on the bundled example finds the 3 known errors.
9. **README:** add a GUI section.
10. **Verify:** run `pytest -q`, start the server and run one live agent assessment (about $0.02).
11. **Commit and push** `gui-console`.
